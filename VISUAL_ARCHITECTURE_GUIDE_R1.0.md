### **PREAMBLE: Effective Upon Execution of Master Services Agreement**

This Visual Architecture Guide ("Guide") is incorporated by reference into the Master Services Agreement ("MSA") between **Consultant** and Stakeholder as MSA_TEMPLATE | **Section 1.2 (Structural Framework)**. This Guide defines the *geometric, cognitive, and operational topology* governing all Statements of Work ("SOW").

**APPLICABILITY NOTE:**

- **Annexes A, B, C** apply to all engagements immediately upon MSA execution.
- **Annex D** activates upon specific election within an SOW Section 4 (Payment Schedule).
- **Binding Effect:** Definitions herein supersede general industry standards regarding project phases, milestones, and payment triggers.
    - A = WHAT EXISTS (geometry: invariant across all projects)
    - B = WHAT IT MEANS (semantics: invariant across all stakeholders)  
    - C = HOW IT OPERATES (workflow: invariant within engagement type)
    - D = WHAT IT COSTS (value: specific to individual SOW/contract)`

***INTEROPERABILITY NOTE:***

- *The Red/Blue chromatic schema defined in Annex B §1 establishes a default semantic polarity (Blue = Consultant / Red = Stakeholder). However, this polarity is **invertible by context**. In certain analytical compositions (e.g., the Chiral SOP Schema), color assignments may flip to serve **differentiated analysis**—where the diagram uses color to explore the inverted relationship between parties rather than assign fixed ownership.*
- ***Rule:** Color alone does not determine contractual jurisdiction. The glyph operator (● ○ ◆ ■ etc.) and its position relative to the Mirror Axis (M) determine jurisdiction. Color encodes **cognitive mode and relational dynamics**; geometry encodes **legal boundary**. When color and geometry conflict, **geometry controls**.*
- ***Rationale:** Fixing color to a single semantic across all possible diagrams collapses the system's ability to represent chiral/mirror scenarios. A practitioner must be able to draw "what does the world look like if Red is the Consultant?" without rewriting the legal framework. The geometry (nodes, foldlines, axes) remains invariant; the color is the analytical lens.*

# **ANNEX A: CONSTITUTIONAL GEOMETRY**

**DEPENDENCY NOTE:**
*Annex B depends on Annex A. Annex C depends on A+B. Annex D depends on A+B+C. Each layer inherits and extends; none overrides the geometric absolutes of its predecessor.*

**Purpose:** Defines the structural topology (X/Y axes), geometric primitives, and governance logic governing work flow.

### **Article 1: Topological Definitions**

| **Axis** | **Definition** | **Cognitive Mode** | **Professional Domain** |
| --- | --- | --- | --- |
| **X-Axis** | Critical Path / Timeline | Temporal (Mode 2) | Project Management |
| **Y-Axis** | Scope Depth / Exploration | Spatial (Mode 1) | Design / Research |
| **Z-Axis (annex d only)** | Value Release Window | Executive (Mode 3) | Finance / Leadership *(See Annex D)* |

### **Article 2: Geometric Primitives**

| **Symbol** | **Primitive** | **Function** | **Legal Implication** |
| --- | --- | --- | --- |
| `◆` | Peak / Vertex | Maximum uncertainty checkpoint | Triggers Validation Cycle |
| `●` | Hold Point | Stable reference / Anchor | Locks scope definition |
| `═══` | Spine | Critical Path (Immutable) | Timeline adherence required |
| `HOLD` | Hold Zone | Protected territory | No unilateral scope expansion |
| `VARIES` | Varies Zone | Flexible scope area | Adjustments via Change Order |
| `⊂` | Incorporation Vector | One-way governance binding | SOW ⊂ MSA inheritance |
| `≪` | Conflict Precedence | Hierarchy Axiom | Outer document controls conflict |
| `∉` | Negative Space | Scope exclusion boundary | Work outside requires Change Order |
| `⊕` | Deposit Ignition | Phase entry precondition | Work starts upon deposit clearance |
| `Ω` / `φ+` | Pivot Point | Directive Switch | Governance mode change (see §3) |
| `⫤` / `M` | Mirror Axis | IP Boundary | Divides Consultant/Client jurisdiction |
| `◊` | Bottom-Up Mode | Discovery / Exploration | Pre-Pivot Directive |
| `▶` | Top-Down Mode | Execution / Delivery | Post-Pivot Directive |
| `~~~` | Meander Line | Deep associative path | Justifies extended divergence pricing |
| `───` | Short Path | Linear efficiency path | Standard timeline execution |
| `■` | Decision Gate | Binary Lock (Lock/Unlock) | Triggers payment obligation |
| `↗` | Diverging Angle | Scope expansion | Additive thinking phase |
| `↙` | Converging Angle | Scope narrowing | Synthetic extraction phase |

### **Article 3: Directive Switch Protocol**

**Definition:** The Pivot Point (Ω) governs a **switch** in governance directive, not a role inversion of personnel. Personnel remain assigned; the directive governing their work changes.

**Protocol:**

1. **Before Ω (Diamond 1):** Bottom-Up Discovery. Team generates insights; Client validates problem definition.
2. **After Ω (Diamond 2):** Top-Down Execution. Team delivers against specs; Client accepts deliverables.
3. **Signaling:** Transition marked by node shape change (`●` → `■`) and color shift (Blue → Red).

**Constraint:** Running Bottom-Up logic after Ω constitutes Misaligned Directive. Running Top-Down logic before Ω constitutes Premature Execution.

### **Article 4: Constraints & Symmetry**

- **Length A (Divergence Width):** Variable. Wide divergence justifies increased pricing depth (Meander Logic).
- **Length B (Convergence Width):** Must equal Starting Width. Convergence absorbs all divergence; orphaned scope triggers Change Order.
- **90° Intersections:** Maintains independence of X (Time) and Y (Scope). Prevents temporal pressure from collapsing spatial exploration.
- **Reflection Symmetry:** Required across Mirror Axis (M). Asymmetric diamonds indicate scope drift.

### **Article 5: Reading Modes**

- **Linear (Waterfall):** Traverse left→right along X-Axis. Applied to fixed-scope, AEC, Design-Build engagements.
- **Figure-8 (Agile):** Trace cyclical pattern through Diamond 1 & 2. Applied to iterative, retainer, SaaS engagements.
- **Application:** SOW specifies Reading Mode. Payment Gates apply identically across both modes.

# **ANNEX B: MARKUP DIALECT**

**Purpose:** Standardizes annotation semantics, color encoding, and glyph operators for contract negotiation and documentation review.

### **Article 1: Unified Chromatic Schema**

**Layer 1: Contractual Jurisdiction**

- **Blue:** Consultant Sovereignty (IP, Methodology, Raw Materials).
- **Red:** Stakeholder Pressure (Scope, Cost, Timeline Requirements).
- **Black:** Neutral Infrastructure (Timeline, Critical Path, Binding Clauses).

**Layer 2: Cognitive Mode Indicator**

- **Blue:** Spatial Cognition / Mode 1 / Divergent Exploration.
- **Red:** Temporal Cognition / Mode 2 / Convergent Delivery.
- **Black:** Shared Binding Structure.

**Implication:** Blue territory grants Consultant ownership of judgment and synthesis. Red territory grants Client direction on delivery requirements.

### **Article 2: Core Glyph Operators**

| **Mark** | **Meaning** | **Implication** |
| --- | --- | --- |
| `○` | Ambiguity Trap | Requires explicit definition before signing |
| `△` | Risk Alert | Potential breach of Non-Extraction or Sovereignty |
| `✕` | Removal Request | Party wishes to delete clause; must be replaced |
| `=` | Confirmation | Both parties agree on wording as written |
| `➜` | Flow | Directional sequence of workflow |
| `┄┄┄` | Parallel Track | Collaborative lane (non-critical path) |

### **Article 3: Annotation Validity Protocol**

1. **Markup Validity:** Handwritten or digital annotations on contract drafts constitute binding offers to amend if initialed by the opposing party.
2. **Conflict Resolution:** In conflict between typed text and marginalia, the **most specific annotation closest to the operative clause controls**, provided it bears initials of both parties.
3. **Crossing Violation:** Requesting work defined in Project Brief but excluded from SOW negative space (∉) triggers automatic Change Order evaluation under MSA §5.0.
4. **Digital Sign-off:** Electronic signatures imply acceptance of all unresolved markings as final compromise positions unless explicitly reverted in writing prior to signing.

# **ANNEX C: SOP LAYER MAPPING**

**Purpose:** Aligns Standard Operating Procedure (SOP) layers with Intellectual Property (IP) status and governance protocols.

### **Article 1: Layer Hierarchy**

| **Layer** | **Output** | **IP Status** | **Deliverable Form** |
| --- | --- | --- | --- |
| **L1: Diagnosis** | Problem Framing / Root Cause | Consultant IP (Raw Synthesis) | Strategic Diagnosis Blueprint (PDF/SVG) |
| **L2: Framework** | System Design / Principles | Consultant IP (Logic Structure) | Visual Map (PNG/SVG + Vault Link) |
| **L3: Synthesis** | Final Integration / Artifacts | Client License (Limited Use) | Ratified Decision Artifacts (PDF) |

**Clause:** Client receives license to L3 Decision Artifacts only. Intermediate synthesis materials (L1–L2 drafts, prompt logs, judgment matrices) remain exclusive property of Consultant under Sovereign AI Principles.

### **Article 2: Three-Axis Governance Protocol**

| **Axis** | **Owner** | **Tool** | **Update Frequency** | **Trigger** |
| --- | --- | --- | --- | --- |
| **X (Timeline)** | Project Manager | Gantt / Scheduler | Weekly | Delay > 5 days = Notice Required |
| **Y (Scope)** | Design Lead | Model / System | Daily | Drift > 15% = Change Order Eval |
| **Z (Value)** | Finance / Principal | Accounting | Per Invoice | Delay > 24hrs = Breach of Flow (Annex D) |

### **Article 3: Project Health Assessment**

**Equation:** Project Health = f(X_adherence, Y_optimization, Z_realization)

- **X_adherence:** On timeline? (±5% threshold)
- **Y_optimization:** Divergence/convergence balance maintained?
- **Z_realization:** Cash flow matches effort expenditure?

**Protocol:** If any axis fails, project enters Warning Status. If two axes fail, Suspension Protocol activates per MSA §3.1(c).

### **Article 4: Meeting Protocol**

| **Type** | **Cadence** | **Role** |
| --- | --- | --- |
| **Progress** | Weekly / Bi-Weekly | Track status; Not payment triggers |
| **Phase Gate** | End of Phase | Deliverable presentation; Invoice trigger |
| **Board / Executive** | Major Milestones | Formal sign-off; Payment gate |
| **Final Handoff** | Completion | License transfer; Final payment |

### **Article 5: Directive Switch Signaling**

| **Signal** | **Before Ω (Bottom-Up)** | **After Ω (Top-Down)** |
| --- | --- | --- |
| **Node Marker** | `◊` (Open Diamond) | `▶` (Filled Triangle) |
| **Questions** | "What if?" / "Why?" | "When?" / "How much?" |
| **Feedback** | Exploratory, Open-ended | Actionable, Time-bound |
| **Documentation** | Research Notes | Technical Specs |

# **ANNEX D: VALUE & PAYMENT ARCHITECTURE**

*(Optional | Activated Upon SOW Election)*

**Activation:** Included only if selected in SOW Section 4. If omitted, standard MSA payment terms apply without dimensional tracking.

### **Article 1: Z-Axis Definition**

**Definition:** Z-Axis = **Value Release Window** (Temporal, not Spatial).

- **Dimension 1 (Height):** Dollar amount authorized/released at node.
- **Dimension 2 (Depth):** Payment window duration (Net-0, Net-15, Net-30).
- **Dimension 3 (Density):** Number of signatories required (1 vs. Board Vote).

**Behavior:**

- **Grows:** At phase gates when deliverables + approvals align.
- **Shrinks:** During Change Orders, disputes, or scope reductions.
- **Flat:** During divergent phases (No payment for exploration).
- **Peaks:** At convergent handoff nodes (Delivery + Acceptance).

**Constraint:** Z cannot release until **BOTH X and Y reach node position**:

1. X = Timeline reached milestone (On Schedule)
2. Y = Scope converged sufficiently (Deliverable Ready)
3. Z = Payment authorized (Client Approval Obtained)

### **Article 2: Payment Status Glyphs**

| **Symbol** | **Meaning** | **Status** |
| --- | --- | --- |
| `●` (Solid) | Payment Received | Closed |
| `○` (Dashed) | Payment Pending | Open |
| `⊗` (Red Border) | Payment Overdue | Breach Trigger |
| **Node Size** | Invoice Amount | Large ($30K+) / Med ($15K-30K) / Small (<$15K) |

### **Article 3: Value Release Windows (Industry Alignment)**

**Standard Distribution (AEC / Design-Build):**

1. **Kick-off:** 10-20% Upfront (Deposit Ignition ⊕)
2. **Phase 1 Handoff:** 20% (SD Approval)
3. **Phase 2 Handoff:** 20% (DD Approval)
4. **Midpoint (Ω):** 20% (Directive Switch Confirmation)
5. **Pre-Completion:** 10-15% (Permit Set / Spec Issuance)
6. **Close-out:** 10-15% (Substantial Completion)

### **Article 4: Breach of Flow (Graduated Enforcement)**

1. **Level 1 (Delay > 5 Days):** Z-freeze. Work pauses. Notification issued.
2. **Level 2 (Delay > 15 Days):** Z-freeze + Interest Accrual (1.5% Monthly).
3. **Level 3 (Delay > 30 Days):** Suspension Protocol. Contract termination rights activate per MSA §3.1(c).
